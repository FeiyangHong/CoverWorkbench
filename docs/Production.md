# 制作主页、统一目录与 MSST

推荐流程是 **MSST 分离 → SV 制作 → Studio One 混音 → 工作台字幕与视频**。歌词、音符、发音和调声继续在 SV 中完成。

## 一首歌，一个目录

点「新建 / 导入工程」可以从 WAV / FLAC 原歌曲开始、先建空项目稍后添加素材，或导入已有 SVP。空项目需填写歌曲名称。目录名使用英文，可含空格，例如 `Artist - Song`；相同名称另建 `_v2`，不会覆盖。内部记录编号只用于关联，不用作新建文件夹名。

```text
projects/Artist - Song/
  source/               原歌曲副本
  separation/Run 01/    每次分离的输入、所选结果、日志和任务记录
  working/sv/           SV 工作副本 / 建议另存位置
  working/sv2/          SV2 工作副本
  working/lyrics/       歌词处理文件
  snapshots/sv/         导入时的 SVP 快照
  studio-one/           新建 Song、SV 副本、媒体、预设和 Mixdown
  video/                关联视频的新工程、下载、准确预览和成片
  exports/              音频、歌词、罗马音、字幕和交付包
  analysis/             新工程的工作台记录
  workspace.json        目录归属与结构
```

已有歌曲可在主页点「统一今后的输出」，指定一个英文名称。原来的 SVP、Song、视频 project.json、字幕、样式、音频偏移和旧导出保留原位置及关联；不移动或重建创作工程。新输出改用统一目录，旧视频结果仍能在历史中打开。主页支持打开文件夹、复制目录和查看各阶段位置。

目录统一针对工作台发起的工具任务。独立运行的 SV / Studio One 不会被后台改写保存路径：已有工程请在软件中将新渲染指向主页给出的目录，或者继续登记它的实际文件。新建的 SV 工作副本与 Studio One Song 已设置自己的音频输出位置。试听缓存与服务器运行文件继续放在 runtime，不混入作品目录。

## 自动分离和登记

1. 单独安装 [MSST-WebUI](https://github.com/SUC-DriverOld/MSST-WebUI) 与自己的模型。在「素材分离 → 服务设置」选择安装目录；Windows 安装包的 `workenv/python.exe` 会自动识别。也支持从已设置 EXE / LNK 识别安装目录，或填写自己的 MSST Python 环境。
2. 选择歌曲，进入「素材分离」。已登记的原歌曲自动作为输入；第一次也可浏览或粘贴带引号的 WAV / FLAC 路径。
3. 默认先使用 big7 分离完整人声和伴奏；需要时可追加 karaoke，输入选择 big7 完整人声或原歌曲。也可以选择两步顺序运行。点击「开始分离并自动登记」。从这里发起的任务直接调用已安装 MSST 的 Python API，**不需要同时启动 MSST 网页**。

| 流程 | 模型 | 自动登记 |
| --- | --- | --- |
| 原歌曲 → 完整人声 / 伴奏 | big_beta7.ckpt | vocals（含和声）、accompaniment |
| karaoke：完整人声或原歌曲 → 主声 / 其余声部 | mel_band_roformer_karaoke_becruily.ckpt | lead、harmony |
| 两步分离 | 上述两模型顺序运行 | 四类素材；第二步可选第一步完整人声或原歌曲 |

这两个流程按模型配置中的 stem 名精确路由。第一步的 other 是伴奏，第二步的 Instrumental 是和声，不能混为一谈。**karaoke 输入原歌曲时，Instrumental 结果可能同时包含伴奏，不能保证是纯和声**；界面会提示这一点，原歌曲也不会登记为完整人声。若配置的 stem 定义不同，会报错而非猜测。当前自动流程仅支持这两组已验证映射；其他模型可继续使用独立 MSST 页面。

每次任务独立放在 `separation/Run 01`、`Run 02` 等目录；保留输入副本、输入哈希、request.json、msst.log 和 job.json。结果文件统一命名为 `Vocals.wav`、`Instrumental.wav`、`Lead.wav`、`Harmony.wav`，位于各自角色子目录。任务成功退出、所选流程结果完整且音频时长检查通过后，才统一登记；失败或取消不会登记部分结果，也不会替换旧素材。期间手动更改过的路径优先保留，并在任务结果注明。结果存在不代表分离质量已人工试听确认。

完成后，SV 提取音符时优先使用主声；没有拆主声时可使用完整人声。建混音工程自动带入伴奏。在本曲上下文中新建 Song 时，默认位置是本曲 `studio-one`，也能切换到 Songs 或自定义目录；成功后登记新的 Song 与它实际引用的 SVP。

网页仅在有运行任务且分离页可见时查询任务状态。关闭标签页不会取消任务；可在任务卡片取消。后台运行中的分离任务会阻止“彻底退出”，避免留下半成品；强制终止 Windows 工作台时，所属模型进程也会退出。重启后中断任务不会自动重跑。

## 生成 SV 起始工程

在「素材分离 → 用这些素材开始 SV 制作」选择 SV1 / SV2、BPM 和已登记的音频，点「生成新的 SVP」。默认选主声（没有则完整人声或原歌曲）与伴奏。生成位置为 `working/sv/Session 01/project.svp` 或 `working/sv2/Session 01/project.svp`，同名顺延版本，始终新建。

所选素材复制到该 Session 的 `Media`，校验源文件与副本 SHA256，并从 0 秒加入音频参考轨；另附一个不指定声库的空白演唱轨。参考轨默认静音，音符提取时在 SV 选择所需人声音轨；自行选择购买的声库、语言并校对。生成器不会自动识别歌词、检测 BPM 或操作正在打开的 SV 窗口。SV1 使用版本 153，SV2 使用版本 196 的音频轨结构；已做结构和文件检查，仍需在对应安装版本中实际打开确认兼容性。

默认保留当前 SVP 路径关联。只有勾选「登记为本曲当前 SV 工程」才将新文件用于后续混音 / 视频交接；已有 SVP 和未保存的原生编辑不会被覆盖。打开新工程文件夹后，可从对应 SV 版本加载 `project.svp`。

## 继续使用 MSST 原界面

启动 MSST 后默认在工作台内打开，也可取消勾选「自动在工作台内打开」或使用新标签页。连接就绪后直接加载；启动时约每 0.8 秒检查一次，复用启动请求结果，避免额外连续探测。切换工作区保留 iframe，只有收起时才卸载。地址仅接受回环 HTTP，探测不跟随重定向。MSST 自动换端口时填写实际地址。

**独立 MSST 网页发起的任务不会被工作台自动认领**，以免将另一首歌的结果登记过来。使用「登记已有结果」选择其文件。工作台不修改 MSST 全局输入输出配置，不安装或下载模型。独立 MSST 进程需自行关闭，收起 iframe 不会结束它。

## 工程关联与迁移

「管理文件路径」管理实际使用的原歌曲、完整人声、主声、和声、伴奏、SVP、Song 和混音。支持文件浏览、引号路径、复制路径与文件管理器定位。

- **复制到项目并使用（默认）**：新选或更换的外部文件复制到本曲目录，保存后登记副本。原歌曲放在 `source`，手动导入的分离结果放在 `separation/imported`，成品混音放在 `exports/audio`。已有项目内文件直接使用；相同内容复用副本，同名不同内容另存 `_v2`，不会覆盖旧文件。
- **仅引用原路径**：直接登记所选文件，不复制；移走或删除该文件会导致引用失效。
- 旧登记不会自动迁移。勾选 **同时收纳已登记的外部素材**，才会把未更换的已有外部文件一起复制；未选择收纳的路径保持原样。主页标明“项目内”或“外部引用”。

外部 SVP 收纳至 `working/sv/Imported SV 01` 或 `working/sv2/Imported SV 01`，复制参考音频并更新副本中的引用和渲染输出目录；保留音符、声库与调声参数。项目内的 SVP / Song 若仍引用外部输入，也会另建完整副本，避免原地修改。新建 / 导入已有 SVP 也按此原则归集参考音频，后续原生打开及混音入口使用工作副本，导入快照保留原始内容。修改外部原文件不会自动同步到工作副本。

外部 Song 收纳至 `studio-one/Imported Mix 01`。读取工程包内的显式文件 URL、相对媒体 URL 和受支持的 SV1 / SV2 外部 SVP 插件状态，将依赖文件及 SVP 的参考音频一起收纳并更新副本引用；其他插件状态保持原字节。工程包内已有嵌入媒体直接保留。**不会盲目复制 Song 所在的整个文件夹**。输入依赖丢失或无法识别的目录引用会阻止登记，请先在 Studio One 中归集外部文件，或明确选择仅引用。插件内部私有路径、采样器音色库及授权不属于可自动归集范围，仍需本机安装；文件检查不代表原生打开或试听验证。

一次保存只有在复制和源文件校验全部通过后才更新登记；失败会回滚本次新建副本，旧登记保留。原文件始终不改写。打开工程只请求原生软件加载磁盘文件；更换 SVP 不会重新解析旧校对记录。

音乐与视频只需关联一次。已有视频的字幕、样式与对时继续保留；登记文件和进入视频不会覆盖它们，更新视频音频或字幕仍需在关联窗口明确操作。未来输出集中到统一目录，旧工程不必搬家。

本机设置保存在 `config/settings.local.json`，素材表在 `config/project-assets.local.json`，统一目录映射在 `config/workspaces.local.json`，视频关联在 `config/video-links.local.json`。新位置的视频工程通过 `projects/video/.folders.json` 索引。所有个人记录和生成文件均被 Git 忽略。

跨设备迁移时需备份工程、媒体和本机记录，并修复其中的绝对路径；这项功能不自动重写任意 SVP / Song / 视频的媒体引用。仓库不附带 MSST 引擎、模型、歌曲或付费软件。
